Set it up in 10 minutes

Run the Mailroom on your machine, connect your laptop, and watch a first parcel arrive; then, if you want, put the Hub in the cloud.

Path A runs everything on your own computer, so you can try it with nothing to pay for. Path B puts the Hub on Cloudflare, so apps in the cloud can reach it. The order is always the same: start the Hub, sign in, make a contract, make a key, connect the laptop, send a parcel.

Before you start

  • A Mac, and Node.js. The Mailroom was built and tested on Node 24. The daemon runs TypeScript files directly, so your Node must be able to run .ts files without a build step.
  • The project folder, the-mailroom, open in a terminal.
  • For the laptop to run claude tasks, Claude Code installed. You do not need it for the echo test below.
  • For path B only: a Cloudflare account.

Path A: try it on your machine

  1. Install. 
    npm install
    You should see the packages install with no errors.
  2. Make your settings file. 
    cp .dev.vars.example .dev.vars
    Open .dev.vars and set OWNER_PASSWORD (what you type to sign in) and SESSION_SECRET (a long random string). Both are placeholders until you change them.
  3. Start the Hub. 
    npm run dev
    You should see Wrangler say it is ready on http://localhost:8787. Leave this terminal open.
  4. Sign in. Open http://localhost:8787 and type your OWNER_PASSWORD. You should land on the Overview page. It says the laptop is "out to lunch". That is right: no laptop is connected yet.
  5. Make a contract. Go to Contracts and press New contract. Give it a name, one folder (for example ~/mailroom-play), keep echo ticked, and save. The box on the right, "In plain words", reads the contract back to you.
  6. Make a key. Go to Keys and make a new key. Pick the contract. You should see the key once, starting with mr_live_. Copy it now and keep it for step 9. It is never shown again.
  7. Get the laptop credential. Go to Laptop and press Rotate credential. Confirm. You should see a credential starting with mrd_, once. Copy it.
  8. Connect the laptop. In a second terminal, in the project folder: 
    node daemon/cli.ts login --url http://localhost:8787 --credential mrd_...
node daemon/cli.ts run
    You should see "Saved to ..." and then mailroom daemon -> http://localhost:8787. On the Laptop page the status turns to connected. (Once you have a mailroom command, you can type mailroom login and mailroom run instead. There is no ready-made file: run npm link in the project folder, or put a one-line script on your PATH. The mailroom command shows how.)
  9. Send an echo parcel. In a third terminal, with your key: 
    curl -X POST localhost:8787/api/jobs \
  -H "Authorization: Bearer mr_live_..." \
  -H 'content-type: application/json' \
  -d '{"task":"echo","args":{"text":"hello"}}'
    You should get back something like {"id":"p_...","state":"queued"}.
  10. Watch it arrive. Open Parcels. Your parcel is there and, a moment later, it says done. Open it to see the tracking steps and the result, {"echo":"hello"}.

Stop the daemon with Ctrl+C and send another parcel. It sits as queued and the Laptop page shows it in "In the queue". Start the daemon again and it runs by itself.

Try a refusal. Send {"task":"read_file","args":{"path":"~/mailroom-play/a.txt"}}. The contract did not allow read_file, so you get a 403 and a reason, and the parcel shows as refused.

Keep the laptop connected

run stops when you close the terminal. To keep the laptop connected after a reboot, install the background service (macOS only). These lines assume you have the mailroom command (see The mailroom command); otherwise use node daemon/cli.ts in its place:

mailroom login                 # asks for the Hub URL and the credential (hidden)
mailroom service install       # starts at login, restarts if it stops
mailroom service status        # installed? running? does the Hub accept the credential?

You should see "Running (pid ...)". The log is ~/Library/Logs/mailroom-daemon.log.

Run only one daemon: the service or a manual run, not both. They would take over from each other.

If you rotate the credential, the running daemon exits and the service retries every 30 seconds until it has the new one. Run mailroom login with the new credential, then mailroom service install again.

Path B: put the Hub on Cloudflare

Do steps 5 to 10 of path A again afterwards, with your own Hub address instead of localhost:8787.

  1. Log in to Cloudflare. 
    npx wrangler login
    A browser window opens. Approve it.
  2. Deploy first. 
    npm run deploy
    The Worker has to exist before it can hold secrets. You should see the address of your Worker, on workers.dev. Until the secrets are set, sign-in fails closed with an error. That is safe, not a bug.
  3. Set the two secrets. 
    npx wrangler secret put OWNER_PASSWORD
npx wrangler secret put SESSION_SECRET
    Wrangler asks you to type each value. Use a strong password and a long random string.
  4. Sign in. Open https://<your-hub> and type the password. You should see the Overview page. Make a contract, a key and a laptop credential exactly as in path A, steps 5 to 7.
  5. Point the laptop at the Hub. 
    mailroom login --url https://<your-hub> --credential mrd_...
mailroom run
    The Laptop page shows connected.
  6. Point the extension at the Hub. If you use the browser extension, put the same address in its options page. See The browser extension.
  7. Send a parcel with the same curl command, using https://<your-hub>/api/jobs.

Only your sign-in page is reachable without signing in. Everything else, including these docs, is behind the owner sign-in. Pick a password you do not use elsewhere.

Under the hood: what each step changed
  • .dev.vars is read only by npm run dev. In the cloud the same two values are Worker secrets.
  • Making a key stores only a hash of it. Making a laptop credential does the same. That is why each is shown once.
  • mailroom login writes the Hub URL and the credential to a private file in ~/.mailroom (readable only by you).
  • The first time you rotate, the Laptop page shows "none yet" before and a hint of the new credential after.

If something looks wrong

You seeLikely cause
401 bad_key from curlThe key is mistyped, revoked, or its contract has expired.
Parcel stays queuedThe laptop is not connected. Check the Laptop page.
Daemon exits at onceThe credential was rotated or is wrong. Run mailroom login again.
