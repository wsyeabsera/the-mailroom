Projects

A project is a label that groups keys, so you can see one app's keys, parcels, commands and events in one place.

A project is for looking, not for permission. It never allows, denies or limits anything. Contracts on the Hub and the policy on your laptop stay the only gates. Create a project per app, move that app's keys into it, and the Projects page shows what each app is doing right now.

What a project is, and is not

A project isA project is not
A name, an optional folder, notes and a colourA permission. Putting a key in a project changes no contract.
A group of keys (a key is in one project, or in none)A folder rule. The folder you type is informational; the contract's folders decide what a key may touch.
A view of those keys' parcels, plus the commands tagged to itA way to run something. A tag on a command lists it; it does not allow it.

Keys with no project sit under Unassigned, a built-in entry that always exists. It is not a real project: you cannot edit, rename or archive it. A new key lands there unless you pick a project, and existing keys stay there until you move them.

The Projects page

Open Projects in the admin app. Each project is a card showing the laptop's state, what is running now (with a progress bar when the job reports a percentage), how many parcels are queued, the last run, today's done, failed and refused counts (since 00:00 UTC), and the number of active keys. Unassigned is always the last card. Archived projects are tucked under a fold at the bottom.

Press New project and give it a name (1 to 60 characters, unique among live projects). Folder (~/... or /...), notes (up to 2000 characters) and a colour are optional.

A project opens in six tabs:

TabShows
OverviewRight now, notes, and its keys at a glance.
ParcelsThe 20 latest parcels of the project's keys.
KeysIts keys (revoked ones too), a Move button on each live key, and New key in this project.
CommandsCommands tagged to the project or allowed by its keys' contracts, with a check column. See below.
EventsEvents about the project, its keys and its parcels, from the latest 500.
SettingsEdit name, folder, notes and colour; archive or unarchive.

The project tag in commands.json

A command in ~/.mailroom/commands.json on the laptop can carry "project": "pr_1000", the id of a project (shown in its address and in the API). The tag does one thing: it makes the command appear in that project's Commands tab. Nothing else changes. A job still needs a contract that names the command and a laptop policy that allows it. See The mailroom command for the file.

The Commands tab and its badges

The tab lists every command that is tagged to the project, plus every command named by the contract of one of the project's live keys. For each one it shows whether the laptop has it, which project it is tagged to, which keys allow it, and a check. The check is ok or one of three badges:

BadgeMeansUsual fix
Tagged to another project on the laptopA key here allows the command, but commands.json tags it to a different live project.Change the tag, or move the key.
Tagged to a project that is missing or archivedThe tag names a project that does not exist or is archived (a typo, or the project was archived).Fix the tag or unarchive the project.
Allowed by a key's contract, but not on the laptopA contract names the command, but the laptop's last report does not list it, so a parcel for it will fail on the laptop.Add it to commands.json (the daemon sends the new list when it next connects).

If the laptop has never reported (a daemon that has not connected since projects arrived), the tab says so, shows "unknown" in the laptop column and cannot raise the third badge. Restart the daemon and it sends its list. A badge is advice. Nothing is blocked because of one.

What the laptop reports, and never reports

When the daemon connects it sends one report with every command in commands.json:

  • Reported: the command's name, its project tag, its arg specs (name, type, required, max length, allowed values) and its timeout.
  • Never reported: the script path, the working folder, any file content, environment, or secrets. A missing, unreadable or not-0600 file reports nothing.

The Hub stores the latest report only, keeps at most 200 commands with 20 args each, and silently drops anything malformed. It treats the report as untrusted display data. The Hub uses it for three things: the Commands tab, GET /api/commands (so an app can see a command's arg specs before it sends), and an early check of a run parcel's args, refused with the same message the laptop would give. It never grants a job. The laptop checks every job against its own file again.

Archive rules

  • You can archive a project only when it has no active keys. Otherwise the Hub answers 409 has_active_keys with the count, and nothing changes. Move the keys or revoke them first.
  • An archived project is hidden from the home page (it sits under the fold), cannot receive keys (moving or creating a key into it is refused), and keeps all its history. A laptop tag pointing at it shows the "missing or archived" badge.
  • Unarchive brings it back. If a live project took its name meanwhile, you get 409 name_taken: rename one first.

How to move a key

  1. Open the key's current project (or Unassigned) and its Keys tab.
  2. Press Move... on the key and choose a live project, or Unassigned.
  3. Press Move key. The key's secret, contract and history do not change; the next parcel simply counts under the new project. The Hub records a key.moved event.

When you hand out a new key you can pick its project in the same form. Over the API it is PATCH /admin/keys/:id with {"project_id": "pr_1000"} (or null). Claude can set a project only when it creates a key; moving an existing key and archiving are yours to do.

Make a project, move one key into it, and send an echo parcel with that key. The project's card shows it under Today, and its Events tab shows key.moved and the parcel.

Under the hood
  • Tables: projects, a nullable keys.project_id, and laptop_report (one row, the latest hello). Routes are on HTTP API.
  • Events: project.created, project.updated (also for an unarchive), project.archived and key.moved. See Events.
  • GET /admin/laptop now also returns commands (name, tag, timeout) and commands_reported_at.
