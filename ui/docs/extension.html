The browser extension

A small Chrome extension puts the number of parcels waiting for your approval on your toolbar, so you do not have to keep the admin app open.

It only looks. It shows a badge, a popup and a side panel, and it can send a notification when a new parcel needs you. To approve or decline, it opens the admin app. It talks only to the Hub address you give it.

What it shows

The badge on the toolbar icon tells you the state at a glance. The extension asks the Hub every 30 seconds.

  • The count wins. If parcels are waiting you see the number, orange when the laptop is connected and amber when it is away. Approvals work while the laptop is away, so the number matters more than the warning.
  • Over 99 waiting shows 99+.
  • If nothing is waiting but the laptop is away, you see an amber ! instead.
  • If you have not set a Hub address yet, there is no badge, and the tooltip says to set it in Settings.
  • Hover the icon for the plain-words version, such as "The Mailroom: 2 waiting for your approval (laptop is out to lunch)".

The popup

Click the icon. The popup shows the laptop status, today's counts, the parcels that need you (each with a Review button) and the five latest events.

  • Review opens that parcel in the admin app in a new tab.
  • Open The Mailroom jumps to a tab you already have open, or opens one.
  • Open side panel shows the same lists in Chrome's side panel. It is read-only and refreshes by itself every 15 seconds.
  • If something is wrong the popup says so, with one button: "Open settings" (no address yet), "Sign in" (you are signed out) or "Retry" (cannot reach the Hub).

Notifications

When a parcel newly starts waiting for your approval, you get one desktop notification: "p_1001 is waiting for your approval". Click it to open the Approvals page.

  • Once per parcel. Another check will not notify again for the same parcel.
  • Not on the first check. Right after you install it, or change the Hub address, parcels that are already waiting do not all ring at once. It only tells you about new ones. The same holds after you close and reopen the browser: the list of notified parcels is cleared then, so the first check afterwards never notifies. A parcel that began waiting while Chrome was closed gives no notification; look at the badge or the popup.
  • The list of parcels it has already told you about lives in session storage only. It is not saved to disk and is cleared when the browser closes.

Install it

The extension is not in the Chrome store. You load it from the project folder. This works in Chrome 116 or newer.

  1. Open chrome://extensions and switch on Developer mode (top right).

  2. Click Load unpacked and choose the extension folder inside the project.

  3. Open the extension's settings: right-click its icon and choose Options.

  4. Paste the Hub address, for example https://<your-hub>. No path after it. Click Save and connect.

  5. Chrome asks you to allow access to that one address. Allow it.

  6. Sign in to the Hub in a normal tab once. The extension uses that sign-in. When it works, the settings page says "Connected as owner".

Plain http:// is accepted only for localhost and 127.0.0.1, so you can try it against a local copy. Anything else must be https://.

Pin the icon: click the puzzle piece in Chrome's toolbar, then the pin next to The Mailroom. Then the badge is always visible.

What it can and cannot do

It canIt cannot
Show how many parcels wait, who sent them and what task they areApprove or decline a parcel
Show the laptop status and the latest eventsCreate or revoke keys, edit contracts, rotate the credential
Notify you about a new waiting parcelSign in for you, or see your password
Open the right page of the admin appTalk to any address other than your Hub

Why no approve button? Every action in the admin app is checked by the Hub: it only accepts them from its own pages. An extension is a different origin, so the Hub would refuse it. That is a good thing. A decision should happen on a page that shows you the full text of what will run, and Review takes you there in one click.

Privacy

  • It only talks to the Hub address you set. No analytics, no remote code, no other hosts.
  • Chrome only lets it reach that one address, because you allow it in step 5.
  • The address is kept in Chrome's synced storage, so it may follow your browser profile to other computers. The list of notified parcels stays in session storage and is cleared when the browser closes.
  • It reads with your normal sign-in cookie. It never asks for or stores your password.

Not tested. The extension was checked in a real Chromium with a throwaway profile against a real local Worker: the badge, the notifications logic, the popup, the side panel and the signed-out states. Three things were not tested.

  • The permission prompt from step 5. Automation cannot click it, so the test granted access to localhost ahead of time.
  • Google Chrome and Brave. Only Chromium was used.
  • The operating system's notification itself. The test checks that the extension asked for one, not that it appeared on screen.

If one of these breaks for you, it is a real finding. Tell the project owner.
