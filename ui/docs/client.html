Use it from another project

One small file lets another app, or a Cloudflare Worker, send parcels to your laptop and follow them.

The helper is client/mailroom-client.mjs. It has no dependencies and uses only fetch, so it runs in Node 18+ and in a Worker. Copy the file into your project.

What you set up once

  1. In the admin app, make a contract that allows the run task and the command you want, then make a key on it. Copy the key (mr_live_...); it is shown once.
  2. Keep the key as a secret, never in code. In the other project: npx wrangler secret put MAILROOM_KEY. For local work put MAILROOM_KEY=mr_live_... in its .dev.vars.
  3. Register the command on your laptop so the daemon knows what tvdash-scan means (see The mailroom command).
  4. Test against a local Hub: run npm run dev in this repo (wrangler dev), and use http://localhost:8787 as the URL.

The five calls

CallWhat it does
submit(task, args, {idempotency?, label?})Sends a parcel. Returns {id, state}. idempotency is sent as the Idempotency-Key header: a repeat within 24 hours returns the same parcel (a different task or args under the same key is a 409 idempotency_conflict). label (1 to 60 characters, optional) tags the parcel, for example "test"; it shows on the Parcels page. A refused parcel comes back with state:"refused" and a reason; other errors throw a MailroomError with status and code.
get(jobId)Reads the status: state, result, reason, and progress: {text, pct?} while it runs.
wait(jobId, {onProgress, intervalMs, timeoutMs})Polls until the parcel finishes (default every 1 s, up to 5 minutes). onProgress is called each time the progress changes. On timeout it throws but the parcel keeps going.
cancel(jobId)POST /api/jobs/:id/cancel. Stops a queued or running parcel.
ask(prompt, vars, opts)Submits an ask parcel for a prompt registered on the laptop, waits, and returns { output } (parsed JSON when the prompt has a schema). You pass only the variables; the laptop fixes the prompt text, tools, turns and model. opts.resume continues an earlier ask job of the same key. Throws if it fails, is refused or is cancelled.
run(command, args)Submits a run parcel for a registered command, waits, and returns the result. Throws if it fails, is refused or is cancelled.

Progress and cancel are new on the Hub. If your Hub does not have POST /api/jobs/:id/cancel yet, cancel throws a 404 not_found, and jobs simply have no progress.

Example: the tvdash scan

Start the scan, show how far it is, and stop it if it takes too long. This runs as is in a Worker (the key comes from env).

import { createClient } from "./mailroom-client.mjs";

export default {
  async fetch(request, env) {
    const mr = createClient({ url: env.MAILROOM_URL, key: env.MAILROOM_KEY });

    // 1. Start it. Reusing the same idempotency string is safe on a retry.
    const sub = await mr.submit("run", { command: "tvdash-scan", args: {} }, { idempotency: "scan-2026-11-18" });
    if (sub.state === "refused") return new Response(sub.reason, { status: 403 });

    // 2. Show progress while it runs. Give up after 2 minutes.
    try {
      const job = await mr.wait(sub.id, {
        intervalMs: 2000,
        timeoutMs: 120000,
        onProgress: p => console.log(`scan: ${p.text}` + (p.pct != null ? ` (${p.pct}%)` : "")),
      });
      return Response.json(job.result);
    } catch (e) {
      // 3. Too slow: cancel the parcel.
      if (e.code === "timeout") { await mr.cancel(sub.id); return new Response("scan cancelled", { status: 504 }); }
      throw e;
    }
  },
};

If you do not need the steps, the short form is one line: const result = await mr.run("tvdash-scan", {}).

If something goes wrong

  • 401 bad_key: the key is wrong, revoked, or its contract expired.
  • refused: the contract does not allow that task or command; the reason says which.
  • Stuck on queued: the laptop is off or asleep. Stuck on waiting_approval: approve it in the admin app.

The raw routes behind these calls are on HTTP API.
