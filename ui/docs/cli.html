The mailroom command

Five commands run on your laptop to connect it to the Hub, keep it connected and check on it.

mailroom login saves where the Hub is and the laptop's secret. mailroom run connects and does the work. mailroom service install does the same in the background on a Mac. mailroom status asks the Hub "do you accept me?". mailroom logout forgets the secret.

mailroom is not installed by itself: the project has no ready-made file called mailroom. To get the command, either run npm link in the project folder (it uses the bin entry in package.json), or put a one-line script named mailroom on your PATH: exec node /path/to/the-mailroom/daemon/cli.ts "$@". Without either, run node daemon/cli.ts <command> from the project folder wherever this page says mailroom <command>. Run it with no arguments to print the help.

login

Saves the Hub address and the daemon credential. Both come from a flag, or from an environment variable, or from a prompt, in that order.

mailroom login [--url URL] [--credential mrd_...]

The credential prompt is hidden: your typing does not appear, so nobody looking over your shoulder (or at a screen recording) sees it. Paste it and press Enter.

  • The URL must be http:// or https://. A trailing slash is removed.
  • The credential must start with mrd_. Anything else is refused and nothing is saved.
  • login does not contact the Hub. Run mailroom status afterwards to find out if it works.

A value passed as --credential mrd_... ends up in your shell history and shows in the process list. For a real credential, use the hidden prompt, or MAILROOM_CREDENTIAL from a safe place.

run

Connects to the Hub, receives jobs and does them. It runs until you stop it with Ctrl+C. If the connection drops it reconnects by itself. If you have not logged in it says "Not logged in. Run mailroom login first." and exits with 1.

It stops by itself in two cases, and says why: the credential was rotated or is wrong, or another daemon took over. Details are on The laptop and the daemon.

status

Shows the saved settings and then makes one plain HTTP request to the Hub to see how it answers. It opens no daemon connection and never prints the credential.

hub: lineMeaning
accepted (a laptop is connected)The Hub knows this credential and a laptop is connected right now. Exit code 0.
accepted (no laptop connected right now)The Hub knows this credential, but no daemon is connected. Exit code 0.
rejected (credential not accepted)Wrong or rotated credential. Run mailroom login. Exit code 1.
unreachable (...)No answer within 8 seconds: wrong address, no network, or the Hub is down. The message in brackets says what the network reported.
unknown (this Hub is older than v0.3.3 and has no safe check; redeploy the Hub, or use `mailroom run`)The Hub is too old to answer the check. Redeploy it.
unexpected HTTP <n>The Hub answered with a status the check does not know. See Troubleshooting.

Exit code 0 only when the line starts with accepted; every other result exits with 1.

mailroom status and mailroom service status ask the Hub a read-only question: does it accept my credential, and is a laptop connected? They never connect as a daemon and never replace the running one, so they are safe to run while the daemon is working. A Hub older than v0.3.3 has no such check, and status says so instead of guessing: redeploy the Hub.

logout

Deletes ~/.mailroom/config.json. It prints "Logged out." or "Nothing to delete.". It does not touch the background service. A daemon that is already running keeps its connection until it stops, and after that it cannot start again. To fully stop, run mailroom service uninstall first, then mailroom logout.

service install, uninstall, status

macOS only. They manage a launchd user agent (the system's own way to keep a program running) that starts mailroom run at login and restarts it if it stops.

  • install needs you to be logged in. It writes the definition, loads it and waits a couple of seconds to see if the daemon is running. Running it again replaces the running copy. It prints where the log is. Exit 0 if it is running, 1 if not.
  • uninstall stops it and deletes the definition: "Service removed." or "No service was installed.".
  • status prints one line, then asks the Hub the same question as mailroom status. Exit 0 only if the service is running.

Environment variables

VariableUsed byWhat it does
MAILROOM_URLloginThe Hub address, if you did not pass --url.
MAILROOM_CREDENTIALloginThe daemon credential, if you did not pass --credential.
MAILROOM_CLAUDE_TIMEOUT_MSrunHow long a claude task may run, in milliseconds. Default 5 minutes (300000).

A flag always beats the matching variable. One more, MAILROOM_SERVICE_LABEL, overrides the launchd label used by service (default dev.mailroom.daemon).

The Claude plugin also reads MAILROOM_URL (plus MAILROOM_TOKEN, which only the plugin uses). If you have exported MAILROOM_URL for the plugin, mailroom login silently takes it as the Hub address and does not ask you. Unset it first, or pass --url. See Claude and other apps.

Exit codes

CodeMeaning
0It worked. Also: no command given (help is printed).
1It did not work: not logged in, bad input to login, credential rejected or rotated, Hub not accepting, service not running, unknown command.
2Only run: replaced by another daemon.

Files it creates

FileModeHolds
~/.mailroom/0700The folder. Only you can open it.
~/.mailroom/config.json0600The Hub address and the daemon credential.
~/.mailroom/state.json0600The last event number it saw. Lets the Hub and the daemon pick up where they left off.
~/Library/LaunchAgents/dev.mailroom.daemon.plist0644The service definition: the command to run, its PATH and your home folder. No secret.
~/Library/Logs/mailroom-daemon.logdefaultEverything the background daemon prints.

Files in ~/.mailroom are written to a temporary file and renamed, so a crash cannot leave a half-written config.

Example sessions

First connection

$ mailroom login
Hub URL (https://the-mailroom.<sub>.workers.dev): https://<your-hub>
Daemon credential (mrd_...):
Saved to /Users/you/.mailroom/config.json

$ mailroom status
config: yes (/Users/you/.mailroom/config.json)
url: https://<your-hub>
hub: accepted (a laptop is connected)

$ mailroom service install
Installed /Users/you/Library/LaunchAgents/dev.mailroom.daemon.plist
Running (pid 4821). It starts at login and restarts if it stops. Log: ~/Library/Logs/mailroom-daemon.log

The line after Daemon credential (mrd_...): is empty on purpose: that is where you pasted the secret, and the terminal did not show it.

The credential was rotated

$ mailroom service status
service: installed, not running, last exit 1
hub: rejected (credential not accepted)

$ mailroom login --url https://<your-hub>
Daemon credential (mrd_...):
Saved to /Users/you/.mailroom/config.json

$ mailroom service install
Installed /Users/you/Library/LaunchAgents/dev.mailroom.daemon.plist
Running (pid 5107). It starts at login and restarts if it stops. Log: ~/Library/Logs/mailroom-daemon.log

Do a dry run without touching your real setup: HOME=/tmp/mr-test mailroom login writes its files under /tmp/mr-test/.mailroom instead. (Use this only for login, status and run, not for the service commands.) Delete the folder when you are done.
