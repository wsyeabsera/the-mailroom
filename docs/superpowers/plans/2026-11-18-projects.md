# Projects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add projects (a laptop folder plus the keys that use it) to The Mailroom, with a Projects home and a tabbed page per project, then clear the remaining `mailroom-run` Later tasks.

**Architecture:** The Hub (Durable Object SQLite, `src/hub.ts`) owns a `projects` table and `keys.project_id`; the daemon reports its registered command names on `hello`; the pure rules (validation, sanitising the untrusted report, command/mismatch view) live in `shared/projects.ts` so `node --test` can reach them; the Hub is proven by `scripts/e2e.mjs`.

**Tech Stack:** TypeScript (Node 24 type-stripping, no build), Cloudflare Worker + Durable Object, plain ES-module admin UI (no build step), `node --test`, wrangler, Playwright for docs/UI checks.

**Spec:** `docs/superpowers/specs/2026-11-18-projects-design.md` (includes the "Calls made" section; read both).

## Global Constraints

- The UI stays plain HTML, CSS and ES modules, no build step.
- A project grants nothing: contracts (Hub) and `~/.mailroom/policy.json` (laptop) remain the only gates. The Hub treats the laptop report as untrusted display data.
- Report limits: at most 200 commands; names `/^[\w.-]{1,60}$/`; at most 20 arg names of at most 60 chars each; anything else is dropped. Never report script paths or cwd.
- Project ids `pr_1000`, `pr_1001`, ... like the other ids. `folder` is an optional free-text label (`~/` or `/` path), not unique, never compared with anything.
- Existing keys become Unassigned (`project_id` null); nothing is renamed or deleted; an old daemon (hello without `commands`) must keep working.
- "Today" is UTC. Admin API: read needs `read` scope; create, edit, archive and move-key need `write`.
- Schema changes are `CREATE TABLE IF NOT EXISTS` plus a guarded `ALTER TABLE keys ADD COLUMN project_id TEXT` that is safe on every start.
- Existing routes (`#/keys`, `#/parcels`, ...) keep working.
- Run `npm test`, `npx tsc --noEmit`, `node scripts/e2e.mjs` (own wrangler and daemon, temp HOME; never touch the real `~/.mailroom` or launchd service `dev.mailroom.daemon`), `node scripts/docs-check.mjs` (needs `PLAYWRIGHT_CORE=/Users/yab/Work/ws-command/node_modules/playwright-core`).

## Review Focus

1. Project name blank, 61 chars, or duplicated by an archived project: 422 with a field error; duplicate names allowed only if one is archived.
2. Laptop report with 500 commands, a 10 KB name, non-string entries or a non-array: sanitised to a valid short list, never an error that drops the connection.
3. Archiving a project that still has active keys: refused with a message naming how many; archived project rejects a key move into it.
4. A contract that allows a command nobody tagged, and a command tagged to a project that does not exist: both appear with a mismatch badge, none crash the page.
5. A daemon that never sends `commands`: Commands tab says "laptop has not reported commands", the rest of the project page works.
